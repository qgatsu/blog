## 手牌の復元

復元自体は素直. 配牌を `Counter` で持ち,ツモで足し,打牌と副露の `consumed` で引く.

```python
def aggregate_game(events: list[dict[str, object]]) -> None:
    """1半荘を頭から再生し,各打牌の時点の手牌を復元する."""
    hands: list[Counter[str]] = []
    melds: list[int] = []

    for ev in events:
        t = cast(str, ev["type"])
        if t == "start_kyoku":
            # 全4人の配牌がここに入っている
            tehais = cast("list[list[str]]", ev["tehais"])
            hands = [Counter(canon(x) for x in th) for th in tehais]
            melds = [0, 0, 0, 0]
        elif t == "tsumo":
            hands[cast(int, ev["actor"])][canon(cast(str, ev["pai"]))] += 1
        elif t == "dahai":
            a = cast(int, ev["actor"])
            remove(a, [canon(cast(str, ev["pai"]))])
            # ここで hands[a] が「打牌直後の手牌」になっている
            ...
        elif t in ("pon", "chi", "daiminkan", "ankan"):
            remove(cast(int, ev["actor"]), cast("list[str]", ev["consumed"]))
            melds[cast(int, ev["actor"])] += 1
        elif t == "kakan":
            # 加槓は手牌から1枚出るが,副露の数は増えない
            remove(cast(int, ev["actor"]), cast("list[str]", ev["consumed"]))
```

注意が要るのは加槓（`kakan`）. 既存のポンに1枚足す形なので手牌は1枚減るが,**副露の数は増えない**. 他の副露と同じ扱いにすると枚数がずれる.

復元がずれていないことは,打牌のたびに次の不変条件で自己検証している.

```python
if sum(hands[a].values()) != 13 - 3 * melds[a]:
    c.bad_handsize += 1
```

打牌直後の門前手牌は,副露1つにつき3枚減った `13 - 3 * melds` 枚になるはず. 全プロジェクトでこのカウンタが 0 であることを確認したうえで集計している. 復元を自前で書くときは,この種の不変条件を必ず1つ入れておくとよい. イベントの取りこぼしは黙って数字を歪めるだけで,エラーにはならない.

## 結果を表す2つの指標

**指標1: 成立率**

```
成立率 = P(ルールが真 | トリガーが成立した)
```

「1を切った後に2を手出しした（トリガー）とき,4を持っている（ルール）確率」のような,そのまま読める確率.

**指標2: リフト**

```
リフト = 成立率 − シグナル無し率
```

「シグナル無し」は,**同種のイベントのうち,条件を満たさないもの**. 全打牌の平均でも,ランダムな手牌でもない.

ここは効き方が大きい. たとえば「逆切り（内側牌の後に外側牌を手出し）」を見るとき,対照を「全ての手出し」にすると,その中に逆切り自身が含まれて差が薄まる. 逆に対照を「全打牌」にするとツモ切りが混ざって別の理由で差が付く. 対照は**トリガーと排他な同種イベント**（＝外側牌の手出しだが,先行する内側牌が無いもの）に取る.

2つ両方を見る理由:

- 成立率が高くてもリフトが 0 なら,それは「もともとよくあること」で,その捨て牌から読めたわけではない.
- リフトが大きくても成立率が 0.1 なら,傾向はあっても実戦で押し引きを変えるほどの確度はない.

## 一番やりやすい失敗：巡目交絡

**条件を満たす群は巡目が遅い側に偏る**,というだけの理由で,ほとんどのセオリーが「成立している」ように見える.

具体例は「123と持っていて4を引いたら1を切る（スライド）」. ブロック（234や345の3枚揃い）が実際に確定しているかを直接判定した結果.

| 群 | n | ブロック確定率 | 巡目標準化後のリフト |
|---|---|---|---|
| 2→1 と手出し・字牌手出しあり | 104,349 | 0.177 | +0.015 |
| 2→1 と手出し・字牌手出しなし | 306,477 | 0.081 | −0.054 |
| シグナル無し（先行牌なし） | 11,022,078 | 0.048 | — |

素で比べると 0.177 対 0.048 で **3.7倍**,いかにも強いセオリーに見える. ところが巡目を揃えると **+0.015** しか残らない.

理由は単純で,「先に2を切って,後で1を手出しする」という条件は捨て牌が2枚以上溜まらないと成立しない. 一方でブロックは巡目が進むほど自然に揃う. 比べていたのは「スライドしたかどうか」ではなく,**主に「序盤かどうか」**だった.

対策として,打牌 index を5バケットに層別し,条件群の巡目分布に合わせて対照群を標準化している. これを入れると,効果が縮むテーマ（スライド）とほとんど縮まないテーマ（間隔手出し）がはっきり分かれる. **標準化前後の差が大きいテーマほど,元の主張は疑ったほうがいい**.

牌譜解析に限らず,観察データで「条件Aのとき結果Bが起きやすい」を見るときは,**条件Aの成立自体が時間経過を要求していないか**を最初に疑う価値がある.
